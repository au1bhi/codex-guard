## 仍然存在的边界

1. **无法保证零扣费。** 轮询、中断和信号有延迟，远端已接收的请求不受本地暂停直接控制。中断 RPC 失败会报告失败；没有账户端扣费上限的证据。
2. **实验性版本兼容。** 实机读取验证限于 CLI 0.160.0。旧版本、远程服务器、不同提供商或多个账户不保证受同一额度窗口正确覆盖；当前本地 daemon 的额度不能被当作所有账户/模型的统一账单。
3. **全局 watch 的作用范围。** 管理当前用户已识别的本地 CLI，并读取 daemon 上已加载回合。暂停和终止属于显式全局控制，不提供可靠的每个 CLI 与每个 daemon thread 的一对一映射。
4. **自动续跑默认开启。** 会话已完成也可能收到新“继续”。不需要该行为时显式使用 `--no-auto-continue`。
5. **终端启动确认有限。** 终端启动器退出码只说明启动请求被接受，不能证明目标会话已经稳定载入。超时会停止本轮降级；没有执行真实桌面自动恢复测试。
6. **兼容旧快照。** 无完整进程身份的旧 PID 不自动唤醒；用户可显式 `resume`。手动唤醒本身可能覆盖额度保护。
7. **平台退化。** 缺少 pidfd 的系统使用身份检查后发送信号，仍存在检查与信号之间的极短竞争窗口。原子状态写入保护文件完整性，但外部 CLI/daemon 状态与守护操作并非一个事务。
8. **包装模式能力收窄。** `run` 只保护子进程，不再通过全局会话恢复函数操作其他任务，也不承诺远端中断。

滚轮修复已更新本机现有 codex-top 的目标可执行文件，未重启真实 systemd 服务。三个入口及服务布局的完整更新仍使用 README 的安装命令。

## 操作入口简化

按用户要求，安装后 PATH 中只保留 `codexguard-start`、`codexguard-stop`、`codex-top`。后台程序移至 `~/.local/lib/codex-guard/codex-guard`，旧别名在更新时清理。监控界面仅保留查看、刷新、退出和调频。

新的关闭命令停止服务后，只解除快照记录且身份匹配的客户端暂停；不终止客户端、不发送续跑消息。这是用户显式关闭保护的行为，与监视器意外退出时保持暂停的策略不同。

## 滚轮误退出修复

curses 和 ANSI 界面曾把鼠标报告开头的 ESC 误当退出键。现在过滤完整的 CSI/SGR 和 X10 鼠标报告，ESC 不再退出；仅 q/Q 或 Ctrl+C 退出。ANSI 输入按原始字节读取，避免文本缓冲与 select 导致输入滞留。新增 curses 事件及真实 PTY 回归测试。

## 界面集成控制

`codex-top` 现提供 g 守护开关、a 自动继续开关、p/c 暂停/唤醒及空格手动继续。自动设置保存为状态目录内 0600 权限的 quota_guard_settings.json；后台每轮重新读取，运行状态通过 quota_guard_runtime.json 确认，界面区分已配置与待应用。关闭自动继续同时关闭空闲续跑和恢复时自动消息；显式手动消息独立处理。服务操作失败会提示并恢复停止标记，控制操作由串行后台线程执行。已更新本机可执行程序，更新时保留守护的运行状态。

## 空格手动继续修复（2026-10-08）

旧实现只向首个 idle 会话执行 codex queue，未区分空白会话，也未确认新回合启动；首个失败会阻止后续目标。现在跳过无任务历史、忙碌及子代理会话，对所有可续跑的已加载根会话重新检查状态，再通过当前 daemon 的 turn/start 发送文本。成功必须包含服务端确认的回合 ID 和有效状态；失败不自动重发，界面显示目标与结果并继续处理其他目标。请求保留会话已有权限与模型设置。

新增 7 项测试覆盖空格分发、多目标、失败隔离、额度保护、状态变化、启动确认，以及真实 Unix WebSocket 上的请求与响应。测试没有向真实业务会话发送消息。本机可执行程序已更新。
